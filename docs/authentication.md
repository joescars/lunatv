# Authentication and network exposure

LunaTV defaults to `AUTH_MODE=session`. Guide pages, live viewing, and `/stream/*` playback remain public for older Roku clients; admin pages, recording access, and mutations require authentication. Anyone who can reach a public live endpoint can start a tuner/transcode, so keep the server on a trusted LAN, behind a VPN, or behind an authenticated reverse proxy. Set `AUTH_PUBLIC_LIVE=0` to require a login or bearer token for live access too. `/healthz` is public; `/stream/metrics` requires admin access.

## Built-in login (recommended for browser use)

Run `node scripts/auth-setup.js` in an interactive terminal. It prompts for an admin password (at least 12 characters), prints a password hash and session secret for the deployment `.env`, and displays an optional Roku/API token **once** on the terminal. Do not copy the plaintext password or token into the repository, logs, or a shared chat. Keep `.env` private (`chmod 600 .env`). Docker Compose passes the variables through to the app; local Node runs do **not** load `.env` automatically, so export them in the shell or pass them through your process manager. You can also run `node scripts/auth-setup.js password`, `token`, or `secret` separately. The `*_FILE` equivalents of the password hash, session secret, token hash, and proxy secret can read files mounted by a secrets manager.

Set `AUTH_ADMIN_PASSWORD_HASH` and `AUTH_SESSION_SECRET` for an admin login. The username defaults to `admin` (`AUTH_ADMIN_USERNAME`). Without configured users or a token, protected routes fail closed with 401; live TV stays public unless disabled as above. Session cookies are HTTP-only and SameSite=Lax; they receive the Secure flag for HTTPS requests. Use HTTPS when accessing the service from untrusted networks. `AUTH_COOKIE_SECURE=1` forces that flag (HTTP logins then cannot persist). If TLS terminates at a reverse proxy, configure an appropriate `TRUST_PROXY` value for Express and restrict direct access to the app so clients cannot forge forwarded headers. Sessions expire after 12 hours by default (`AUTH_SESSION_TTL_HOURS`); changing a user's password hash or role, or removing a user, invalidates outstanding sessions. Rotating the session secret invalidates all sessions. Login attempts are throttled per IP in memory; for internet-facing deployments use proxy-level rate limits too.

Optional additional users can be configured with `AUTH_USERS_FILE`, a private JSON array of objects with `username`, `role` (`viewer`, `operator`, or `admin`) and `passwordHash` (generated with the same script). Restart to load changes. Viewers can read recordings and start playback; operators can also set favorites and start, stop, or delete recordings; admins can use `/admin/*` and read stream metrics. Protect the users file with filesystem permissions and never commit it.

## Roku/API token

Set `AUTH_API_TOKEN_HASH` to the hash generated by `node scripts/auth-setup.js token`; `AUTH_API_TOKEN_ROLE` defaults to `operator`. Put the corresponding plaintext token into the Roku's ignored `roku/.env` as `HDHOMERUN_API_TOKEN` and set `HDHOMERUN_WEB_URL`; `roku/deploy.sh` embeds it in the sideloaded package and sends it on API and Video-node requests. A packaged token can be extracted by someone with access to the app package: use a dedicated **viewer** token if only private live/recording playback is needed, or **operator** only when the Roku must change favorites or recordings. Never package an admin token. Rotating a token requires regenerating its hash, updating the server configuration and rebuilding/sideloading the Roku app. Older Roku builds continue to work for public live TV without a token, but cannot access protected recording/mutation routes. Verify playback on a real Roku after enabling private live TV; the automated Roku checks are static only.

Bearer requests may omit browser-only Origin headers; cookie and proxy-authenticated mutations need a same-origin Origin or `Sec-Fetch-Site: same-origin`. The pre-existing origin check still rejects cross-origin mutations even when a bearer token is supplied. Do not use a browser's ambient cookie as an API token.

Use the final LunaTV origin (scheme, host, and optional port) as `HDHOMERUN_WEB_URL`, not a redirect. Roku does not attach the packaged token to other server URLs entered in Settings. Repackage with the correct origin and token when moving to another server.

## Reverse proxy and opt-out

`AUTH_MODE=proxy` trusts `AUTH_PROXY_USER_HEADER` (default `x-forwarded-user`) **only** when the request also has the correct `x-lunatv-proxy-secret` header. Set a strong `AUTH_PROXY_SECRET` (16+ characters) and have the trusted proxy strip incoming identity/secret headers before injecting its own. Do not expose the Node port directly; bind it to loopback or a private interface accessible only to the proxy. Configure `AUTH_PROXY_ADMINS`, `AUTH_PROXY_OPERATORS` as comma-separated usernames; others receive `AUTH_PROXY_DEFAULT_ROLE=viewer`. Supply a Roku token separately if needed. An origin or same-origin fetch header is still required for browser mutations through the proxy.

`AUTH_MODE=off` deliberately removes access control and logs a warning. Use it only on a fully trusted network or for synthetic tests. The same-origin mutation check remains active. Never use this mode to expose the service on the internet.

For local changes use the development Compose override (`docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build`); verify that the image you deploy actually contains authentication before relying on it. After deployment, check an anonymous request to `/admin` returns 401 or a login redirect, `/healthz` returns 200, and a signed-in admin can reach `/admin`. A public `/stream/*` endpoint is not evidence that admin access is unprotected.
